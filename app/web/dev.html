AI는 공고 해석, 업종 분류, 설명문 작성만 합니다. 금액과 감면 판정은 코드가 계산합니다.

AI가 없어도 금액은 똑같이 나옵니다. 추출, 업종 분류, 설명문마다 대체 경로가 있습니다.

2단계는 결정적 파이프라인입니다. 도구를 고정된 순서로 부르고, 같은 입력에는 같은 금액이 나옵니다. 도구는 pipeline.Deps로 주입하므로 테스트에서는 가짜 도구로 바꿔 끼웁니다.

요청 흐름

  1. 공고 입력

    공고 두 건을 붙여넣거나, 샘플 버튼(가상 회사 2쌍)을 누르거나, 공고 PDF를 불러옵니다. PDF는 pdf.js가 브라우저 안에서 글자만 뽑고 파일은 서버로 보내지 않습니다. 두 칸이 차면 자동으로 비교를 시작합니다.

  2. 추출: POST /api/extract

    코드가 전화번호와 이메일을 가린 뒤 Gemini에 보냅니다. Gemini는 조건과 근거 문장을 JSON으로 돌려줍니다. 코드는 근거가 원문에 있는지 대조하고, 공고 안의 지시문은 따르지 않습니다. 빠진 조건이 있으면 코드가 되물을 질문을 고릅니다.

  3. 확인 (필요할 때만)

    추출값을 근거 문장과 함께 보여주고 사용자가 확인합니다. 연봉이나 근무지가 없거나 서로 다르면 계산하지 않고 묻습니다.

  4. 계산: POST /api/compare

    resolve_region → get_rent_stats → check_relief_rules → simulate 순서로 실행합니다. 화면은 템플릿 설명으로 금액을 먼저 띄웁니다. 조건이 모자라면 계산하지 않고 추가 입력을 요청합니다.

  5. 설명: POST /api/explain

    같은 요청으로 AI 설명문을 받아 바꿔 끼웁니다. 설명문 속 숫자가 계산 결과와 다르면 버립니다. 두 번 통과하지 못하면 템플릿 문장을 그대로 둡니다. AI가 쓴 글에는 "AI가 생성한 답변" 표시를 붙입니다.

  6. 회사 정보: GET /api/company

    결과가 나온 뒤 비동기로 국민연금 가입 사업장 API에서 실제 회사의 가입자 수를 가져옵니다. 참고로만 보여주고 계산에는 쓰지 않습니다.

결과 화면이 보여주는 것

  • 시나리오 4개: none, current_law, proposal_base, proposal_pref
  • 연차별 표와 10년 누적 남는 돈, 손익분기 연봉
  • 감면 가능성(likely / uncertain / unlikely)과 이유, 인사팀에 확인할 질문
  • 근거와 가정, 월세 수집 기준일

AI와 코드의 경계

숫자 계산과 규칙 판정은 코드가 합니다. AI는 문서 해석과 문장 작성만 맡고 금액을 직접 만들지 않습니다.

일담당방법AI 장애 때
공고에서 조건 읽기AI연봉, 근무지, 회사 규모, 업종, 복리후생을 근거 문장과 함께 추출합니다.샘플 공고는 저장된 추출을 씁니다. 그 밖의 공고는 오류를 알립니다.
근거 대조코드근거 문장이 원문에 없으면 그 값을 버립니다.영향 없음
개인정보 가림코드전화번호와 이메일을 LLM에 보내기 전에 가립니다. 나이·병역 등 사용자 정보는 LLM에 보내지 않습니다.영향 없음
되물을 질문 고르기코드빠졌거나 서로 다른 조건을 규칙으로 찾아 묻습니다.영향 없음
업종 분류AI사업 내용을 읽고 업종을 분류합니다.키워드 규칙으로 처리합니다.
월세 조회코드수집 스냅샷에서 시군구 원룸 월세를 읽습니다. 런타임에 실거래가 API를 부르지 않습니다.영향 없음
감면 판정코드규칙으로 가능성을 세 단계로 판정합니다. 단정하지 않습니다.영향 없음
금액 계산코드원 단위 정수와 분수 연산으로 계산합니다. float를 쓰지 않습니다.영향 없음. 금액이 같습니다.
도구 호출 순서코드고정된 순서로 부릅니다.영향 없음
결과 설명문AI계산 결과를 문장으로 씁니다. 코드가 숫자를 대조합니다.템플릿 문장을 씁니다.

LLM 설정

  • 주 모델: Google Gemini gemini-flash-lite-latest
  • 대체 모델: gemini-3.5-flash-lite → gemini-3.1-flash-lite
  • 응답 온도 0, 한 번 시도는 8초까지입니다. 429·5xx·시간 초과면 바로 다음 모델로 넘어갑니다.
  • -latest는 별칭입니다. Google이 가리키는 버전을 바꾸면 동작이 달라질 수 있습니다.

24 / 30건가상 공고, 배포 URL 실측 통과
0건금액 추정, 설명문 숫자 불일치, 원문에 없는 근거
78 / 100컨텍스트 없는 새 세션 심사. QA 치명 0건
  • 자동 테스트. pytest 216개가 통과합니다. 계산 모듈은 순수 함수로 두고 단위 테스트를 붙였습니다.
  • 가상 공고 30건. 배포 URL에서 실측해 24건이 통과했습니다. 금액을 추정한 경우, 설명문 숫자가 계산과 다른 경우, 원문에 없는 근거를 낸 경우는 0건입니다.
  • 계산 대조. 계산 모듈과 따로 짠 참고 구현(scripts/calc_ref.py)의 결과를 연봉 2,000만 원부터 2억 원까지 5만 원 간격으로 대조했습니다.
  • 외부 시선 점검. 컨텍스트가 없는 새 세션에 심사와 QA를 맡겼습니다. 심사 78/100, QA 치명 0건이었습니다. 점검 뒤 '현행법 감면 0년 이유' 안내를 추가했습니다.
  • 모델 선택. 11/21 실측에서 주 모델의 추출 중앙값은 3.2초였고 샘플 정답 필드 84/84가 일치했습니다.
