- **버린 대안**

### D-02 LLM 출력은 코드가 검증한다

- **날짜·결정**: 11/20 설계(`docs/agent-spec.md` 4장·8장), 11/21 밤 보강(D-08). 팀 결정, 담당 이동한(에이전트)
- **결정**
  - 추출값: 근거 문장이 원문(개인정보를 가린 본문)에 있는지 본다. 공백을 정리한 뒤 포함 여부로 비교한다. 없으면 값을 "AI 추정"(`inferred`)으로 낮춘다.
  - 연봉: 근거 문장이 원문에 있어야 하고, 환산에 쓴 숫자가 근거 안에 있어야 한다. 아니면 값을 버리고(`missing`) 되묻는다.
  - 설명문: 숫자를 계산 결과로 만든 값 목록(`build_value_list`)과 대조한다. 목록에 없는 숫자가 있으면 한 번 다시 쓰게 한다. 두 번 다 실패하면 템플릿 문장을 쓰고 `ai_generated=False`로 둔다.
  - 화면은 `aiGenerated`가 true이고 `numbersVerified`가 false가 아닐 때만 AI 설명문으로 바꾼다. AI 문장에는 "AI가 생성한 답변"을 표시한다.
- **이유**
  - 대회 규정이다. LLM 결과에는 근거를 함께 돌려주고, 근거가 없으면 "확인 불가"로 답한다.
  - 근거 없는 값을 사용자에게 보여 주지 않는다.
- **버린 대안**
  - LLM이 스스로 검증한다: 같은 모델이 같은 실수를 한다 (보고서).
- **영향과 지켜야 할 것**
  - 검증 규칙을 넓히면 주입 구멍이 열릴 수 있다. 11/21에 실제로 열렸다(D-08). 근거 검증을 고치면 `test_prompt_injection_does_not_change_salary`가 통과하는지 본다.
  - 설명 프롬프트에는 값 목록의 `label` 표기만 준다. 나이와 병역 같은 사용자 정보는 LLM에 보내지 않는다(`test_explain_input_has_no_profile`).
- **관련 파일**: `app/agent/evidence.py`, `app/agent/numbers.py`, `app/agent/explain.py`, `app/agent/extract.py`, `app/agent/mask.py`, `app/web/app.js`(`loadAiExplanation`), `tests/test_agent.py`

### D-04 금액 먼저, AI 설명문은 나중

- **날짜·결정**: 11/21 밤(커밋 `3a746a4`), 김상해
- **결정**
  - 화면은 `/api/compare`를 `options.explanation: "template"`으로 부른다. 서버는 LLM 설명문 없이 금액과 템플릿 문장을 돌려준다.
  - 화면은 결과를 먼저 띄우고, 같은 요청을 `POST /api/explain`에 보낸다.
  - `/api/explain`은 같은 계산을 다시 하고, 숫자 대조를 통과한 AI 설명문과 고지만 돌려준다. 화면은 설명 카드와 고지만 바꿔 끼운다.
  - 늦게 온 이전 요청의 설명문은 버린다.
- **이유**
  - 계산 단계가 LLM을 3~4번 차례로 불렀다. 업종 분류 A, 업종 분류 B, 설명문, 숫자 대조에 실패하면 재작성이다. 그런데 금액에는 LLM이 필요 없다.
  - 계산 API(배포, curl 연속 3회): 7.6~20.9초 → 0.25~1.0초. 같은 인스턴스에서 분류 캐시가 걸린 값이다.

  - 비교 시작부터 결과 화면까지(배포, 브라우저 실측): 6.7~7.7초.
  - 누적 기간 바꾸기: 6~17초 → 화면 다시 그리기 포함 약 1.6초.
- **버린 대안**
  - 한 요청에서 설명문까지 기다리기(이전 방식).
  - 설명문 스트리밍: 숫자 대조 전에는 문장을 보여 줄 수 없다 (보고서).
- **영향과 지켜야 할 것**

### D-05 업종 분류는 동시에 부르고 캐시한다

- **날짜·결정**: 11/21 밤(커밋 `3a746a4`), 김상해. `classify.py`는 에이전트 영역이라 이동한이 검토한다
- **결정**
  - `run_compare`는 공고 A·B의 업종 분류를 동시에 부른다.
  - 같은 모델에 같은 사업 내용 문장이면 앞서 받은 결과를 다시 쓴다(`classify._CACHE`).
  - 캐시에는 실제 LLM이 성공한 결과만 넣는다. LLM이 실패해 키워드 규칙으로 대신한 결과와 테스트용 가짜 LLM의 결과는 넣지 않는다.
  - 캐시는 서버 인스턴스의 메모리에만 있다. 512건이 차면 비운다.
- **이유**
  - 업종 분류 A, B를 차례로 부르는 것이 계산 단계 대기의 일부였다.
  - `/api/explain`과 누적 기간 바꾸기는 같은 조건으로 계산을 다시 한다. 캐시가 있으면 분류를 다시 부르지 않는다.
- **버린 대안**
  - A·B를 차례로 부르기(이전 방식).
  - 인스턴스 밖 공유 캐시: 검토 기록이 없다 (확인 필요).
- **영향과 지켜야 할 것**

### D-17 기회비용 보강: 연봉 인상만 넣는다

- **날짜·결정**: 11/22 02시대, 김상해(대표자). Claude Code에 서비스 경쟁력 점검을 맡긴 뒤 그 제안을 받아들였다.
- **문제**
  - 10년 누적이 1년 값에 10을 곱한 것과 같다. 계산이 연봉과 월세를 고정한다(`docs/calc-rules.md` 1장, `app/calc/scenarios.py`). 서울 예시는 1년 23,119,806원, 10년 231,198,060원이다.
  - D-15에서 정한 이름 「첫 직장, 10년 뒤 경제력」과 맞지 않는다. D-15의 이름은 Claude Code가 제안했다.
  - AI가 맡는 일이 공고 읽기, 규칙으로 고르는 질문, 설명문뿐이다. "계산기에 LLM을 붙였다"는 평을 받기 쉽다(U-7).
- **결정**
  - 공고별 연 인상률 하나를 계산에 넣는다. 1년차 연봉에서 매년 같은 비율로 오른다.
  - AI는 공고 본문에서 인상 단서(연 ○% 인상, 호봉제, 성과급)를 근거 문장과 함께 찾는다. 숫자가 없으면 값을 비우고 사용자에게 묻는다.
  - 인상률 숫자와 금액은 LLM이 만들지 않는다. 계산은 코드가 정수로 한다(D-01, D-02).
  - 손익분기 연봉은 "1년차 연봉" 기준으로 바꾼다.
  - 작업은 W8(`docs/tasks/W8-salary-growth.md`)이다. 기본 인상률은 U-12에서 정한다.
- **이유**
  - 빠진 기회비용 가운데 금액이 가장 크다. 시작 연봉 3,400만 원에서 인상률이 연 1%p만 달라도 10년 세전 합계가 15,715,223원 달라진다(0%와 1% 비교, 원 단위 내림). 지금 화면의 10년 차이(세후 17,684,900원)와 비슷한 크기다.
  - 공고 본문에 단서가 있어서 AI가 근거를 들고 할 수 있는 일이다.
  - 고르지 않은 공고에서 포기하는 차액이 이미 기회비용이다. 빠진 것은 그 차액을 바꾸는 요인이고, 연봉 인상이 그중 가장 크다.
- **버린 대안**
  - 주제를 바꾸기: 22:00 동결까지 20시간이 남지 않았다.
  - 기회비용 금액을 LLM이 추정하기: 대회 규정(금액은 코드가 계산)에 어긋나고 근거를 댈 수 없다.

### U-12 기본 인상률과 샘플 공고

- D-17(W8)에서 공고에 인상률이 없을 때 쓸 값을 정한다.
  1. 기본 0%(연봉 고정). 공고 근거나 사용자 입력이 있을 때만 반영한다. 샘플 공고 한 쌍에 인상 문구를 넣어 시연에서 보이게 한다. (제안)
  2. 공식 통계 하나를 두 공고에 같은 값으로 쓴다. 출처를 찾아야 하고, 두 공고에 같은 값을 쓰면 차액은 조금만 바뀐다.
  3. 회사 규모별 공식 통계를 쓴다. 차이가 가장 크게 드러나지만, 출처 조사와 가정 설명이 가장 많이 든다.
- 1안을 권하는 이유: "근거가 없으면 확인 불가"라는 프로젝트 원칙(`CLAUDE.md`)과 맞고, 데이터 조사가 필요 없다.
- 1안의 비용: 샘플 공고 본문을 바꾸면 `data/samples/*.json`의 `savedExtract`도 바꿔야 한다(이동한 확인).
- 1안에서 샘플 두 공고에 각각 몇 %를 넣을지도 정한다. 값에 따라 10년 결과에서 더 남는 쪽이 뒤집힐 수 있다.
- 정할 사람: 김상해, 이동한 의견(샘플)
