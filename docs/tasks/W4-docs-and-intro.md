## 할 일

1. 소개서는 저장소 밖 파일이다. Claude Code는 그 파일을 고칠 수 없으므로, 바꿀 문장 초안을 채팅으로 만든다. 김상해가 소개서에 옮긴다.
2. W1이 합쳐졌는지 본다. 이름과 숫자는 W1 뒤의 화면 기준으로 쓴다. README와 `docs/ai-usage-log.md`는 W1이 합쳐진 뒤 pull하고 고친다.
3. 소개서 전체의 서비스 이름을 「첫 직장, 10년 뒤 경제력」으로 바꾼다.
4. 프로젝트 요약의 한 줄 설명을 "채용공고 두 개를 넣으면 세금과 월세를 빼고 10년 동안 남는 돈을 비교합니다."로 바꾼다.
   - W8이 합쳐지면 "연봉 인상까지 반영해"를 넣는다. 예: "채용공고 두 개를 넣으면 세금과 월세를 빼고, 연봉 인상까지 반영해 10년 동안 남는 돈을 비교합니다."
   - 문제 정의와 AI 역할은 D-17 기준으로 쓴다.
     - 고르지 않은 공고에서 포기하는 차액이 기회비용이다. 이 서비스는 그 차액을 원 단위로 계산한다.
     - AI는 공고에서 기회비용 단서(연봉 인상률, 호봉제, 기숙사)를 근거 문장과 함께 찾고, 공고에 없으면 묻는다. 금액은 코드가 계산한다.
     - 주거지원금은 추출해서 확인 화면에 보여 주지만 계산에는 넣지 않는다(`app/web/app.js` "계산에는 반영되지 않습니다"). 소개서에 반영한다고 쓰지 않는다.
     - 손익분기 연봉은 "1년차 연봉" 기준이다(W8 뒤).
   - "한계와 다음 단계"에 넣지 않은 기회비용을 적는다. 월세 인상, 통근 시간·비용, 생활비, 지역 청년 지원금, 저축 수익, 이직이다.
5. 소개서 04 기술 스택의 모델을 바꾼다.
   - 주 모델 `gemini-flash-lite-latest`, 대체 모델 `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite`.
   - 호출 방식: OpenAI 호환 주소, JSON 출력, 응답 온도 0, 한 번 시도는 8초까지, 429·5xx·시간 초과면 바로 다음 모델.
   - 바꾼 이유(11/21 실측)와 `-latest`가 별칭이라는 점은 `CLAUDE.md`의 LLM 항목에서 옮긴다.
6. Happy path 설명을 바꾼다. 샘플 공고 → 비교 시작 → 바로 결과다. 연봉이나 근무지가 빠졌을 때만 확인 화면에서 묻는다.
   - 바로 계산할 때 쓰는 기본값(만 27세, 병역 0개월, 2027년 이후 입사, 감면 이력 없음)은 결과 맨 위에 밝힌다는 점도 적는다.
   - Happy path가 들어가는 장은 plan.md 7장 기준으로 05다(확인 필요).
7. 소개서의 금액은 배포 화면이나 계산 모듈 출력에서만 가져온다. 5년 기준 숫자가 있으면 10년 기준으로 바꾼다.
8. 소개서 03의 LLM 역할 서술은 decisions.md U-7 결정을 따른다. 지금 코드는 질문이 템플릿이고 도구 순서가 고정이다. W8 뒤에도 질문을 고르는 것은 규칙이다. AI가 찾는 단서가 늘어난 것만 쓴다.
9. `docs/ai-usage-log.md` 표의 "(팀이 채울 것)" 칸을 채운다. 팀이 한 일은 김상해가 말한 내용만 적는다. Claude Code가 짐작해 채우지 않는다.
10. 합쳐진 PR(W1·W2·W3·W5·W6·W8) 본문의 "Claude Code가 한 일"과 "내가 직접 확인한 일"을 `docs/ai-usage-log.md`에 옮긴다.
11. README Credits의 "확인 필요" 3건을 출처 페이지에서 확인한다. 국토부 전월세 실거래가, 법정동 코드, 인구감소지역 고시다(decisions.md U-9).
12. 확인하지 못한 것은 "확인 필요"를 그대로 두고, 그 사실을 PR 본문에 적는다.
13. README 마지막 줄대로 오픈소스 라이선스를 각 저장소의 LICENSE 파일로 한 번 더 확인한다.
14. README "지금 상태" 표의 LLM 줄은 옛 모델(`gemini-3.1-flash-lite`)로 남아 있다. W1이 고치지 않았으면 주 모델로 고친다.
15. AI 활용내역(제출서 입력란, 3,000자)의 초안을 4항목 순서대로 만든다. 근거는 `docs/ai-usage-log.md`와 agent-spec 13장이다.
16. PR 본문에 "Claude Code가 한 일"과 "내가 직접 확인한 일"을 한 줄씩 적는다.

## 위험과 되돌리는 법

- 팀이 하지 않은 일을 적으면 대회 규정(팀의 주도성)에 걸린다. 팀이 말한 것만 적는다.
- 소개서 숫자가 배포 화면과 다르면 심사에서 신뢰를 잃는다. 숫자는 W1 뒤 배포 화면에서 다시 확인한다.
- `gemini-flash-lite-latest`는 별칭이라 Google이 가리키는 버전이 바뀔 수 있다. 소개서에 이 점을 한계로 적는다.
- 문서에 API 키를 넣지 않는다.
- 합친 뒤 문제가 생기면 병합 커밋을 `git revert`로 되돌린다.
