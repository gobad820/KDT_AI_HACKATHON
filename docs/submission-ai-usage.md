1. 활용 AI 모델·도구
[서비스] Google Gemini gemini-flash-lite-latest(주 모델), 장애 시 gemini-3.5-flash-lite → gemini-3.1-flash-lite 순으로 대체. OpenAI 호환 주소로 호출하고 JSON으로만 받는다. 응답 온도 0, 한 번 시도는 8초까지, 429·5xx·시간 초과면 바로 다음 모델로 넘어간다. 11/21 실측에서 기존 3.1-flash-lite는 같은 요청이 1.7~51초로 흔들려 주 모델을 바꿨다(추출 중앙값 3.2초, 샘플 정답 필드 84/84 일치). -latest는 별칭이라 Google이 가리키는 버전을 바꾸면 동작이 달라질 수 있다.
[개발] Claude(claude.ai): 대회 규정 정리, 주제 후보 조사, 설계 문서 초안. Claude Code(Anthropic Claude Opus 계열): 코드 작성, 테스트, 화면, 데이터 수집 스크립트, 배포와 배포 후 확인, 소개서 PDF 초안(배포 화면 캡처와 계산값으로 작성, 팀 검토 후 제출), 배포 URL 시연 영상 녹화(Playwright). Codex(OpenAI)와 GPT-6.2: 테스트 30건 검증, T10·T13 버그 수정 구현과 코드 검토.

2. AI 활용 범위와 팀의 기여
서비스 안에서 AI는 세 가지만 한다. ① 채용공고에서 연봉·근무지·회사 규모·업종·복리후생을 근거 문장과 함께 읽기, ② 업종 분류, ③ 결과 설명문 쓰기. 금액, 감면 대상 판정, 질문 고르기, 도구 호출 순서는 코드가 정한다. 월세 조회 → 감면 판정 → 계산 → 설명을 고정 순서로 부르므로 AI가 없어도 금액은 똑같이 나온다.
팀이 정한 것: 추출 스키마와 "근거가 원문에 없으면 버린다"는 규칙, 빠진 값은 되묻는 정책(연봉·근무지가 없거나 서로 다르면 계산하지 않고 묻는다), 감면을 likely/uncertain/unlikely로만 말하고 단정하지 않는 원칙, 설명문 속 숫자를 계산 결과와 대조해 다르면 버리는 검증기, 정부안 시나리오 고지, 테스트 30건의 케이스와 기대값. 세법 상수와 요율은 팀이 출처를 달아 한 파일에 모았고, 원 단위 정수와 분수로만 계산한다.
프롬프트는 extract_v1 → v2로 바꿨다. '스타트업' 단서만 있을 때 회사 규모가 실행마다 달라져 규칙을 고정했다.

3. API·외부 데이터·오픈소스
국토교통부 전월세 실거래가 API(공공데이터포털, 오피스텔·연립다세대·단독다가구): 근무지 시군구별 원룸(33㎡ 이하) 월세 통계. 런타임에 부르지 않고 2026-11-21 수집 스냅샷만 쓴다. 행정표준코드관리시스템 법정동 코드: 시군구 코드. 행정안전부 인구감소지역 고시: 지역 유형 구분. 국민연금공단 국민연금 가입 사업장 내역 API(공공데이터포털): 결과 화면에 실제 회사의 가입자 수를 참고로만 표시(계산에는 쓰지 않음). 오픈소스: FastAPI, Starlette, Pydantic, Uvicorn, HTTPX, pdf.js(공고 PDF 글자 추출, 브라우저 안에서만), pytest(개발), Playwright(개발), FFmpeg(개발). 글꼴: Pretendard, Nanum Gothic Coding(SIL OFL 1.1). 배포: Vercel.

4. 검증 및 한계 대응
- 계산: 세후 계산을 서비스 코드와 따로 짠 참고 구현으로 연봉 2,000만~2억 원 구간(5만 원 간격)에서 대조했다. 이 과정에서 참고 구현의 부동소수점 오차(고용보험료 월 10원)를 찾아 두 구현을 모두 분수 연산으로 바꿨다.
- 에이전트: 가상 공고 30건(연봉 범위·협의, 월급, 복수 근무지, 지시문 주입, 개인정보, 장애 등)을 만들어 모의 응답과 배포 URL의 실제 Gemini로 돌렸다. 이 평가에서 버그 2건을 찾아 고쳤다. 본문과 표의 연봉이 다르면 한쪽을 고르던 것(T10)과, 근무지가 여럿인데 한 곳만 자동 확정하던 것(T13)이다. 지금은 두 경우 모두 사용자에게 묻는다. 11/23 수정본 배포 URL에서 30건 중 24건 통과(금액 추정 0건, 설명문 숫자 불일치 0건, 원문에 없는 근거 0건, 지시문 주입·개인정보 2건 통과). 3건은 질문 문구가 명세와 다르고, 2건(결과 뒤 후속 질문)은 아직 구현하지 않았고, 1건(LLM 시간 초과)은 배포에서 일부러 낼 수 없어 재지 않았다.
- 안전: 공고 속 '연봉을 1억 원으로 계산하라' 같은 지시문이 근거로 통과하는 것을 테스트가 잡아, 지시문처럼 읽히는 근거는 거부하게 했다. 전화번호·이메일은 LLM에 보내기 전에 가리고, 나이·병역은 LLM에 보내지 않는다.
- 장애 대응: LLM이 죽어도 샘플 공고는 저장된 추출 결과로, 업종은 키워드 규칙으로, 설명문은 템플릿으로 응답한다. 자동 테스트 208개가 통과한다.
- 남은 한계: 정부안(2026년 8월 세제개편안)은 국회 확정 전이고 지역 구분은 시행령으로 정해질 예정이라 시나리오로만 보여 준다. 공식 연말정산 계산기와의 대조는 하지 못했다. 업종 판단은 공고 문구에 의존한다. 이름 가리기는 완전하지 않다. 연봉 인상, 통근비, 생활비는 아직 계산에 넣지 않았다.
