# 첫 직장, 10년 뒤 경제력: 데이터 명세

- 작성: 2026-11-20(금)
- 주 독자: 김상해(데이터·서버·배포). 통계 규칙은 정상훈, 도구 출력은 이동한도 확인한다.
- Claude가 조사해 정리한 초안이다. 결정과 검증은 팀이 직접 하고, 기획에 Claude를 쓴 사실은 AI 활용내역에 적는다.
- 꼬리표: `[확인]` 11/20에 법령·공식 자료로 확인 / `[2차]` 기사·라이브러리 소스로만 확인, 원문 대조 필요 / `[미확인]` / `[가정]`

## 0. 결정 사항

- 런타임에는 외부 실거래가 API를 부르지 않고 수집 스냅샷만 쓴다.
- 이유 1: 마감(11/23 17시) 뒤에는 데이터를 바꿀 수 없다. 실시간으로 부르면 새 신고분이 들어와 같은 입력의 결과가 달라진다.
- 이유 2: 예선 심사(11/24~11/30)와 본선(12/7)에 외부 API가 멈춰도 서비스가 돌아야 한다.
- 스냅샷에 수집 기준일을 남기고 화면에 "실거래가 수집 기준일 2026-11-22"처럼 표시한다. 응답의 `dataVersion.rent`와 `rent.dataAsOf`가 이 값이다.
- `get_rent_stats`와 `resolve_region`은 스냅샷과 지역 테이블을 읽는 서버 내부 함수다. 입출력 형식은 `docs/api-spec.md`를 따른다.

## 2. 실거래가 API `[2차]`

포털 페이지에는 주소와 필드명이 없어 오픈소스 PublicDataReader 1.1.1.post2 소스에서 확인했다. 활용신청 뒤 기술문서와 Swagger로 확정한다.

| 유형 | 엔드포인트 | 면적 필드 |
|---|---|---|
| 오피스텔 | `http://apis.data.go.kr/1613000/RTMSDataSvcOffiRent/getRTMSDataSvcOffiRent` | `excluUseAr`(전용면적) |
| 단독/다가구 | `http://apis.data.go.kr/1613000/RTMSDataSvcSHRent/getRTMSDataSvcSHRent` | `totalFloorAr`(계약면적) |
| 연립다세대 | `http://apis.data.go.kr/1613000/RTMSDataSvcRHRent/getRTMSDataSvcRHRent` | `excluUseAr`(전용면적) |

- 요청: `serviceKey`(인증키), `LAWD_CD`(법정동 코드 앞 5자리), `DEAL_YMD`(계약년월 6자리, 예: 202610), `numOfRows`, `pageNo`
- 응답: XML. `response.header.resultCode`가 `000`이면 정상이고 항목은 `response.body.items.item`에 있다. 항목이 1건이면 파서에 따라 배열이 아닌 객체로 나오고, 0건이면 `items`가 빈다.
- 오류: 인증키 오류나 한도 초과는 `OpenAPI_ServiceResponse.cmmMsgHeader`의 `errMsg`, `returnReasonCode`로 올 수 있다. 두 구조를 모두 처리한다.
- 건수: 응답에 전체 건수(`totalCount`)가 있으면 받은 건수와 대조한다(필드 유무 확인).

| 구분 | 필드 | 메모 |
|---|---|---|
| 지역 | `sggCd`, `umdNm`, 오피스텔은 `sggNm`도 | 저장 키는 요청에 쓴 5자리 코드 |
| 계약일 | `dealYear`, `dealMonth`, `dealDay` | 계약월로 기간을 자른다 |
| 금액 | `deposit`, `monthlyRent` | 쉼표가 든 문자열. 단위는 만 원으로 알고 있음. 저장할 때 원 단위 정수로 바꾼다 |
| 면적 | `excluUseAr` 또는 `totalFloorAr` | 유형마다 기준이 다르다(위 표) |
| 계약 구분 | `contractType`, `contractTerm`, `useRRRight`, `preDeposit`, `preMonthlyRent` | 갱신 계약을 가려내는 데 쓴다 |
| 그 밖 | `buildYear`, `floor`, `houseType`, `offiNm`, `mhouseNm`, `jibun` | 통계에 쓰지 않는다. 유형에 따라 없는 필드가 있다 |

활용신청 뒤 가장 먼저 확인할 것(금요일 밤, 실제 호출 몇 번으로 끝낸다):

1. 실제 응답의 필드명이 위 표와 같은지
2. `deposit`, `monthlyRent`의 단위(만 원)와 쉼표
3. `contractType`에 들어오는 값(신규, 갱신, 빈 값 등)과 비율
4. `numOfRows`를 크게 줬을 때 한 번에 받는 행 수. 거래가 많은 시군구에서 전체 건수와 비교
5. 승인 직후 키가 바로 동작하는지, https로도 호출되는지

## 3. 수집

호출 단위는 (유형, 시군구 코드, 계약월) 한 건이다. `sgg_12m` 범위 때문에 최근 12개월(2025-11~2026-10)을 받는다. 시군구는 일반구를 포함해 약 250개로 잡았다(정확한 수는 코드 파일에서).

| 범위 | 호출 수 |
|---|---|
| 유형 1종 × 250 × 12개월 | 3,000 |
| 유형 2종(오피스텔, 단독/다가구) | 6,000 |
| 유형 3종(연립다세대 추가) | 9,000 |
| 6개월만 받을 때 | 1,500 / 3,000 / 4,500 |

- 한도: 포털 표기는 개발계정 트래픽 10,000 `[2차]`. 유형마다 API가 따로라 한도가 API별이면 유형당 3,000건으로 여유가 있고, 합산이어도 3종 12개월(9,000건)이 한도 안이다. 다만 재시도 여유가 적으므로 한도가 하루 기준인지, API별인지 신청 화면에서 확인한다 `[미확인]`. 페이지가 나뉘면 호출 수가 늘어난다.
- 속도: 순차 호출에 짧은 간격(0.1~0.3초, 조정)을 둔다. 초당 제한은 `[미확인]`. 호출당 0.3초면 3,000건에 15분 남짓이다(어림).
- 재시도: 실패하면 간격을 늘려 최대 3회. 끝까지 실패한 (유형, 코드, 월)은 실패 목록에 남기고, 다시 돌릴 때 그 목록만 받는다. 0건 응답과 실패를 구분한다.
- 보관: 원본을 SQLite `data/rent.sqlite`의 `rent_deals`에 넣는다(유형, 5자리 코드, 계약월, 보증금·월세 원 단위, 면적, 면적 기준, `contractType`, 수집 시각). 통계는 별도 스크립트가 만든다. 시간이 없으면 통계 JSON만 만든다.
- 로그: 시작·종료 시각, (유형, 코드, 월)별 받은 건수, 실패 목록, 총 호출 수, 필터 전후 건수, 전환율, 스크립트 커밋. 인증키는 남기지 않는다.
- 순서: 토요일 오전에 샘플 공고 지역과 수도권·광역시의 최근 6개월부터 받아 통계까지 연결한다. 나머지 지역과 12개월은 그 뒤에 받는다. 연립다세대는 맨 마지막이다.

## 4. 원룸 필터와 통계 규칙

| 순서 | 규칙 | 메모 |
|---|---|---|
| 1 | 월세가 있는 계약만(`monthlyRent > 0`) | 전세 제외 |
| 2 | 면적 33㎡ 이하 | 오피스텔·연립다세대는 전용면적, 단독/다가구는 계약면적. 기준이 다르다는 점을 화면에 표시 |
| 3 | 갱신 계약 제외 | `contractType`으로 가려낸다. 값이 비어 있는 건은 포함 `[가정]`, 실제 값 분포를 보고 확정 |
| 4 | 명백한 오류값 제외 | 면적 0 이하, 보증금 음수, 계약일 누락. 제외 건수를 로그에 남긴다 |
| 5 | 환산월세 = 월세 + (보증금 − 1,000만 원) × 전환율 ÷ 12 | 전환율 초기값 연 6% `[가정]`. 환산 결과가 0 이하면 제외 |
| 6 | 통계는 p25, 중위, p75, 표본 수 | 선형 보간, 원 단위 정수로 반올림. 유형을 합쳐 하나로 내고 유형별 건수는 따로 저장 |
| 7 | 기간은 계약월 기준 최근 6개월 | 수집하는 달(2026-11)은 빼고 2026-05~2026-10 |

- 계산 예: 보증금 500만 원에 월세 50만 원이면 500,000 + (5,000,000 − 10,000,000) × 0.06 ÷ 12 = 475,000원. 보증금 3,000만 원에 월세 40만 원이면 500,000원.
- 신고분 기준이라 최근 한 달(10월)은 건수가 적게 잡힐 수 있다. 화면에 기간과 표본 수를 함께 보여준다.
- 주거비는 월세만이다. 관리비는 데이터에 없어 넣지 않는다. 화면에 "보증금 1,000만 원 기준 환산"과 전환율 가정을 적는다. 선택 `[가정]`: 보증금이 월세의 240배를 넘는 계약(준전세)은 전환율 가정의 영향이 커서 제외할지 팀이 정한다.

## 5. 표본이 부족할 때

| `scope` | 지역 | 기간 | 쓰는 때 |
|---|---|---|---|
| `sgg` | 해당 시군구 | 최근 6개월(2026-05~2026-10) | 기본 |
| `sgg_12m` | 해당 시군구 | 최근 12개월(2025-11~2026-10) | `sgg`가 30건 미만일 때 |
| `sido` | 같은 시도 전체 | 최근 6개월 `[가정]` | `sgg_12m`도 30건 미만일 때 |

- `sampleCount`가 30 이상이면 `sufficient: true`다. 부족하면 에이전트가 `scope`를 넓혀 다시 부를지 판단한다(`docs/agent-spec.md`).
- `sido`까지 30건 미만이면 `sufficient: false`로 돌려준다. 에이전트는 "확인 불가"로 두고 사용자에게 월세를 직접 받는다(`housing.mode`가 `custom`).
- `sido`는 근무지 주변 시세와 차이가 클 수 있다. 화면은 응답의 `scope`를 보고 "시도 전체 기준"이라고 표시한다. 전남광주통합특별시는 시도 범위가 넓어 옛 광주와 옛 전남을 따로 묶을지 정한다.
- 세 범위의 통계를 미리 계산해 두고 런타임에는 조회만 한다. 인접 시군구 묶음은 MVP에서 만들지 않는다. 시연용으로 `sgg`가 30건 미만인 지역을 한 곳 찾아 둔다.

## 6. 스냅샷과 동결

| 파일 | 내용 | 비고 |
|---|---|---|
| `data/rent.sqlite` | 수집 원본, 테이블 `rent_deals` | 검증·재계산용. 크면 저장소에 넣지 않고 따로 보관 |
| `data/rent_stats.json` | 버전, 수집 기준일, 전환율, 시군구·시도별 통계 | 서버가 읽는 파일. 커밋 |
| `data/regions.csv` | 지역 유형 테이블(8장) | 커밋 |

```json
{
  "version": "2026-11-22",
  "dataAsOf": "2026-11-22",
  "depositBasis": 10000000,
  "conversionRate": 0.06,
  "housingTypes": ["officetel", "detached_multi"],
  "stats": {
    "11680": { "sgg": { "period": "2026-05~2026-10", "sampleCount": 412, "p25": 720000, "monthlyMedian": 850000, "p75": 1010000 } }
  }
}
```

- 위 숫자는 설명용 임의값이고 실데이터가 아니다. `sgg_12m`도 같은 모양으로 같은 코드 아래에 두고, `sido`는 시도 코드별로 한 번만 저장해 `regions`의 `sidoCode`로 찾는다. 유형 값 표기(`officetel`, `detached_multi`, `row_multi`)는 제안이며 `docs/api-spec.md`와 맞춘다.
- 11/22(일) 수집본을 최종본으로 동결한다. 테스트 30건과 소개서 화면 캡처가 같은 데이터를 쓰도록 일요일 오전에 확정한다(제안). `version`이 `dataVersion.rent`로, `dataAsOf`가 `rent.dataAsOf`로 나간다.
- 동결 뒤에는 `data/`를 바꾸지 않는다. 전환율이나 필터를 바꾸려면 동결 전에 통계를 다시 만들고 버전을 올린다. 마감(11/23 17시) 뒤 변경은 규정 위반이고, 복구가 필요하면 같은 파일을 다시 배포하는 것만 한다.
- 토요일 개발 중에는 일부 지역만 든 임시 스냅샷을 쓴다. 버전에 `-partial`을 붙여 최종본과 구분한다.

## 7. 지역 코드

- 법정동 코드(10자리)의 앞 5자리가 시군구 코드다. 실거래가 API의 `LAWD_CD`와 우리 `sggCode`가 이 값이고, 문자열로 다룬다.
- 최신 코드 파일은 행정표준코드관리시스템(code.go.kr)에서 받는다. 폐지된 코드가 섞여 있는지 보고 현재 쓰는 코드만 남긴다(파일의 컬럼 구성은 받아서 확인).
- 일반구가 있는 시(수원시, 창원시 등)는 구 단위 코드로 조회한다. 공고에 시까지만 적혀 있으면 구 코드 여러 개의 거래를 합산해 통계를 낸다. `regions`에 시 단위 행을 두고 `memberCodes`에 구 코드를 적는다(시 단위 코드가 파일에 있는지 확인).
- 이름이 같은 구(중구, 동구, 서구, 남구, 북구, 강서구 등)는 시도 이름과 함께 해석한다.
- 2026년 변경: 전남광주통합특별시가 2026.7.1 출범했다(광주광역시와 전라남도 폐지·통합) `[확인: 다수 보도]`. 출범에 맞춰 법정동·행정동·도로명·기관 코드가 바뀌었다 `[2차]`. 옛 코드와 새 코드의 대응, 2026년 6월 이전 계약월을 어느 코드로 조회하는지는 실제 호출로 확인한다. 그 밖의 변경이 있었는지는 `[미확인]`이라 최신 코드 파일을 기준으로 삼고, 12개월 내내 0건인 코드는 변경을 의심한다.

## 8. 지역 유형 테이블 `regions`

- 식별 컬럼: `sggCode`(5자리 문자열), `sidoCode`, `sidoName`, `sggName`, `aliases`(약칭과 옛 이름), `memberCodes`(시 단위 행의 구 코드 목록)
- 유형 컬럼: `regionClass`, `typeBase`, `typePref`, `prefCandidate`, `classUncertain`, `note`
- 분류 규칙(typeBase, typePref 순): `capital`(서울, 인천, 경기) 1, 2 / `metro`(부산, 대구, 대전, 울산) 2, 3 / `other`(그 밖의 비수도권) 3, 4
- 세종과 옛 광주광역시 5개 구는 `metro`, typeBase 2로 넣고 `classUncertain`을 true로 둔다 `[가정]`. 화면은 "분류 미확정"을 알린다. 옛 전라남도 시군은 `other` `[가정]`.
- `prefCandidate`는 행정안전부 고시의 인구감소지역 89곳 목록을 받아 채운다(여기에 나열하지 않는다). 우대지역 후보일 뿐 확정이 아니다. 정부 설명은 "우대지역은 주로 인구감소지역과 낙후지역" `[2차]`. 통합·편입으로 이름이 바뀐 곳은 코드로 대조한다.
- 비수도권 광역시 등과 우대지역의 구체 지역구분은 2027년 2월 정기 시행령 개정 때 반영될 예정이다 `[2차]`. 그래서 이 테이블은 전체가 `[가정]`이고, 화면은 `proposal_base`와 `proposal_pref`를 항상 같이 보여준다.
- 유형 판정 기준이 근무지인지 사업장 소재지인지 `[미확인]`이라 공고의 근무지로 판정한다 `[가정]`. 유형별 감면기간은 이 테이블에 넣지 않는다(`docs/calc-rules.md`의 상수).

## 9. 근무지 → 코드 (`resolve_region`)

- 입력은 공고에서 뽑은 근무지 문자열(`workLocationText`), 출력은 후보 목록과 `ambiguous`다. 사전(`regions`의 시도명, 시군구명, `aliases`)으로 찾고, LLM이 코드를 지어내게 하지 않는다.
- 절차: 괄호·건물명·층 제거 → 시도 약칭 통일 → 시도 → 시군구 순으로 대조 → 후보 반환. 후보에는 `regions`의 유형 컬럼을 그대로 붙인다.
- 후보가 하나면 `ambiguous: false`. 시도 없이 "중구"만 있거나, 근무지가 여러 곳이거나, 못 찾으면 `ambiguous: true`로 후보(없으면 빈 목록)를 돌려주고 에이전트가 `ask_user`로 되묻는다.
- 동 이름만 있는 주소는 MVP에서 지원하지 않고 되묻는다(동 사전 없음). 옛 이름("광주광역시 서구", "전라남도 순천시")은 `aliases`로 받는다.
- 본사 주소가 아니라 근무지를 넣는다 `[가정]`. 재택·해외 근무는 빈 목록으로 돌려주고 처리는 `docs/agent-spec.md`를 따른다.
