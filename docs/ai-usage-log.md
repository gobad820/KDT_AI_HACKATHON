# AI 사용 기록

AI 활용내역(3,000자)과 소개서를 쓸 때 근거로 삼는다. AI가 한 일과 팀이 판단·수정·검증한 일을 구분해 한두 줄씩 적는다.

| 날짜 | 도구 | AI가 한 일 | 팀이 한 일 (판단, 수정, 검증) |
|---|---|---|---|
| 11/15~11/20 | Claude (claude.ai) | 대회 규정 정리, 역대 수상작 조사, 주제 후보 비교, 기존 서비스와 세법 조사 | 주제 선정 기준과 후보 평가. (팀이 채울 것) |
| 11/20 | Claude | 문서 초안 5종(`brief`, `api-spec`, `calc-rules`, `data-spec`, `agent-spec`) 작성 | (팀이 채울 것: 21시 회의에서 확정·수정한 내용) |
| 11/20 | Claude | 저장소 뼈대 생성: API 타입, 계산 모듈, 감면 판정, 결정적 파이프라인, API 서버, 데이터 스크립트, 에이전트 틀, 화면 3장, 테스트 | (팀이 채울 것: 직접 실행한 결과, 고친 곳) |
| 11/20 | Claude | 계산 참고 스크립트의 부동소수점 오차(고용보험료 10원 미만 버림에서 월 10원 차이)를 찾아 분수 연산으로 고치고 문서 수치를 정정 | (정상훈) 공식 계산기 대조로 확인 |

## 팀이 직접 해야 하는 검증 (AI가 대신하지 않은 것)

- 세후 계산을 국세청 연말정산 모의계산, 4대보험 계산기와 대조 (`docs/calc-rules.md` 8장의 표)
- 세법 조문과 2026년 요율의 원문 확인 (`docs/calc-rules.md` 9장)
- 실거래가 API의 실제 응답으로 필드명, 금액 단위, `contractType` 값 확인 (`docs/data-spec.md` 11장)
- 프롬프트 문장, 되묻기 정책, 테스트 30건의 실행과 결과 정리 (`docs/agent-spec.md`)
- 화면을 실제 브라우저에서 눌러 보기

## 발견한 오류와 보완 (AI 활용내역 ④에 쓸 것)

- 11/20: 참고 스크립트가 부동소수점으로 보험료를 계산해 연 100원 안팎의 오차가 있었음 → 서비스 코드와 참고 구현을 모두 분수 연산으로 바꾸고, 두 구현이 연봉 2,000만~2억 원 구간(5만 원 간격)에서 같은 값을 내는지 대조함
- 11/21: Claude 요금제로는 API 키를 쓸 수 없어 서비스용 LLM을 Gemini로 바꿈(코드 수정 없이 OpenAI 호환 주소 사용). 가상 공고로 시험한 결과 `gemini-2.5-flash`는 신규 사용자 404, `gemini-3.8-flash`·`gemini-3.5-flash-lite`는 503(사용량 과다)이 잦아 `gemini-3.1-flash-lite`를 골랐다. 일시 오류에 한 번 재시도하도록 어댑터를 보완하고 테스트 3건을 더함
- 11/21: 실제 수집 월세가 생기자 테스트 3건이 실패함(테스트가 그때 있는 데이터 파일을 읽음) → `tests/conftest.py`로 테스트는 항상 샘플 스냅샷을 읽게 고정
- 11/21: 화면 디자인을 CSS만으로 다시 씀(Claude, `frontend-design` 스킬 지침 참고). JS가 만드는 클래스 이름과 화면 3장 구조는 그대로 두고, 샘플 1번으로 입력→확인→결과를 데스크톱·휴대폰 폭에서 캡처해 확인
- 11/21: 첫 화면에 예시 애니메이션 추가(라이브러리 없이 CSS+JS). 숫자는 `scripts/build_hero.py`가 계산 모듈과 월세 통계로 만든 `hero.json`만 쓴다. 움직임 줄이기 설정이면 최종 상태만 보여 준다
- 11/21: 사용자 피드백(디자인이 별로)으로 화면을 영수증 컨셉으로 다시 씀. 첫 화면은 영수증 두 장이 출력되고 더 남는 쪽에 도장이 찍히는 장면. 전국 월세 통계(267개 시군구, 2026-11-21)로 첫 화면 숫자를 다시 만듦
