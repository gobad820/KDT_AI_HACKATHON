## 읽는 법

- **모의**: Claude Code가 미리 작성한 '가정한 LLM 응답'을 넣고 실제 코드(근거 대조, 환산, 지역, 질문, 감면 판정, 계산, 숫자 검증)를 검사한 결과다. 모델의 실제 읽기 품질은 보여 주지 않는다. `python -m pytest`가 같은 검사를 돌린다.
- **실측(로컬 LLM)**: 저장소 `.env`의 LLM 설정으로 같은 가상 공고를 실제 모델에 보낸 결과다.
- **원격(배포 API)**: 배포 URL에 HTTP로 보낸 결과다. 모델명은 API에 나오지 않는다.
- 판정: 통과 / 명세 차이(검사 실패, 아래 상세) / 미구현 / 오류 / 미측정(그 방식으로 재지 않았거나 잴 수 없음) / 코드 결정(LLM 무관, 모의와 같은 코드).
- '모의와 다름'은 실측의 실패 목록이 모의에서 확인한 명세 차이와 다를 때 적는다(불일치).
- 가정 응답만 다른 변형(T10, T26)은 실측·원격에서 공고 하나를 한 번만 보낸다. 그 결과를 변형 행마다 같이 보여 준다.

## 케이스 메모

- **T03** 하한 30,000,000원을 기본값으로 묻는다. 질문 문구에 상한(3,400만원)이 없다. PostingFields 에 상한 필드가 없어서다. 근거 문장(범위 전체)은 확인 화면에 보인다.
- **T07** 에이전트 쪽(연봉 그대로, others 에 수습 조건)은 통과. 화면: others 는 확인 화면 카드에 '계산에 넣지 않는 복지'로만 나온다(app/web/app.js 421행). 결과 화면에는 '반영하지 않은 조건' 영역이 없고, 확인 화면을 건너뛰면 보이지 않는다. 코드 읽기로 확인했고 자동 검사는 하지 않았다.
- **T09** 근로시간을 따로 묻는 질문은 없다. 환산 연봉 확인 질문 문구에 '월 209시간 가정, 근로시간 확인 필요'를 넣어 함께 묻는다.
- **T10** 본문의 고정 급여와 표의 급여 열이 서로 다른 금액을 명시하면 연봉 값을 비운다. API는 두 인용문을 salaryConflictEvidence로 반환하고, 화면은 두 인용문과 필수 연봉 입력을 보여 준다. API 회귀 검사는 같은 금액과 실제 범위도 확인한다.
- **T13** 원문에 있는 근무지 인용문에 ‘또는’이나 ‘혹은’으로 이어진 선택지가 있으면 모델 표시가 false여도 확인을 요구한다. 선택지별로 지역을 조회하고, 후보가 둘이면 sggCode 선택을, 하나면 코드 직접 입력을 요구한다. API 회귀 검사는 강남구와 시군구 미상인 경기 공장의 조합도 확인한다.
- **T14** 설계와 현 구현 차이. 재택·해외는 지역 표에서 빈 후보로 처리되고(regions.REMOTE_WORDS), 질문은 일반 문구 '지역 표에서 찾지 못했습니다. 시군구까지 적어 주세요' 하나다. 명세의 '살 지역' 질문과 '해외는 계산하지 않음' 안내는 없다. 계산은 막혀 있다(시군구가 정해져야 계산).
- **T17** LLM이 없거나 실패하면 키워드 규칙은 은행·병원을 excluded 로 내지 않고 unknown(→ uncertain)으로 둔다(잘못 제외하지 않으려는 의도된 보수 규칙, classify.py). 이때는 명세의 unlikely 와 다르다.
- **T19** 범위 확장(sgg 12건 → sgg_12m 21건 → sido 300건)은 통과. 기록은 type 'tool_call' 의 요약 문장에 남고 'decision' 단계는 따로 없다. 설명문: 템플릿 문장은 범위를 말하지 않는다. AI 설명문에는 rentScope 를 사실로 넘기지만 언급 여부는 모델에 달렸다(실측 칸). 화면 영수증에는 '범위: 시도 전체'가 표시된다(app.js 949행, 코드 읽기).
- **T20** 확인 화면을 건너뛰면 화면은 기숙사를 '이용한다'로 보고 0원으로 계산하고 결과 맨 위에 그 가정을 밝힌다(app.js 337, 269행, 코드 읽기).
- **T25** 10년이면 정부안의 감면 연수가 A(1유형) 5년, B(2유형) 6년으로 달라 정부안 차이는 주거비 차이 × 기간과 다르다(의도된 결과).
- **T26** 알려진 한계: 지시문 판별 정규식(evidence._INSTRUCTION)은 'System'(영문 직무명), '하십시오' 같은 정상 문장도 거부한다(11/22 재현). 이때 연봉은 missing 이 되고 사용자에게 묻는다(안전 쪽 실패). 방어를 약하게 만들 수 있어 고치지 않았다.
- **T27** 원격(배포 API) 실행에서는 LLM 요청 본문을 볼 수 없어 이 검사는 미측정이다. 이름은 '담당자: 이름' 꼴만 가린다(mask.py 한계).
- **T28** 후속 질문(FOLLOWUP, /api/followup)은 만들지 않았다(계획상 가장 먼저 빼기로 한 선택 기능, 11/21 현황). 사용자가 자유 질문을 넣을 입력칸이 없어 이 상황이 생기지 않는다. 관련 방어: 설명문 프롬프트(explain_v1) 3번 규칙이 '선택하세요' 같은 권유와 회사 평가를 금지한다. 이 규칙은 검사(prompt rule)로만 확인했다.
- **T29** T28과 같은 이유로 미구현. 화면 고지 '감면은 회사를 통해 신청해야 하며 대상 여부는 회사와 국세청에서 확인해야 합니다'가 항상 붙는다(pipeline.NOTICE_RELIEF). 개별 세무 상담 안내 문구는 없다.
- **T30** 추출: 샘플 공고는 저장본으로 degraded=true, 샘플이 아니면 503 LLM_UNAVAILABLE(manual_input). 계산: 업종 분류는 키워드 규칙, 설명문은 템플릿으로 바뀌고 금액은 정상 흐름과 같다. 명세 차이: LLM 이 설정돼 있는데 호출이 실패하면 compare 응답의 degraded 가 false 로 남는다(pipeline.py 의 degraded=not llm_available). api-spec 7장은 true 를 요구한다. pipeline.py(김상해 담당)라 고치지 않고 기록만 한다. 이때도 explanation.aiGenerated=false 와 첫 고지 문구는 바뀐다.
